You can create usage metrics in two ways:

1. Go to **Settings** > **Customer Analytics** and click **Add usage metric**
2. Open any [customer profile](/docs/customer-analytics/customer-profiles) and click **Add usage metric**

### Configuration options

| Field                  | Description                                                                                         |
| ---------------------- | --------------------------------------------------------------------------------------------------- |
| **Name**               | The column title shown in customer lists                                                            |
| **Interval**           | Time period for the metric: 7, 30, or 90 days                                                       |
| **Format**             | How the value displays: Numeric or currency                                                         |
| **Display**            | How the metric is visualized: Number (default) or Sparkline                                         |
| **Calculation**        | How data is aggregated: Count (default) or Sum                                                      |
| **Property/Column**    | The field to sum. Only shown when **Calculation** is set to **Sum**                                 |
| **Source**             | Where data comes from: PostHog events (default) or a [Data Warehouse](/docs/data-warehouse) table   |

### Data source

Usage metrics can be created from two sources:

#### Events (default)

Match PostHog events tracked by your application. You can add multiple event matchers to include events matching any of them. For example, to track API usage, match events named `api_request` or `api_call`. Property filters let you narrow down what counts—like only counting successful API calls by filtering for `status = 200`.

#### Data Warehouse

Pull data from a synced [Data Warehouse](/docs/data-warehouse) table. This is useful when the data you want to track lives outside PostHog—for example, Stripe charges, Salesforce records, or any external system synced to your warehouse.

When selecting a Data Warehouse table, you must specify:

| Field                | Description                                                                 |
| -------------------- | --------------------------------------------------------------------------- |
| **Table name**       | The synced Data Warehouse table to query                                    |
| **Timestamp column** | The column (or HogQL expression) used to filter by date range               |
| **Group key column** | The column whose value matches your customer's identifier (e.g., `customer_id`) |

<CalloutBox icon="IconInfo" title="Limitation" type="fyi">

Data Warehouse usage metrics currently only render on group profiles, not person profiles.

</CalloutBox>

### Aggregation type

Choose how the metric calculates values:

- **Count** – Tallies the number of events or rows. Use this for frequency-based metrics like API calls or signups.
- **Sum** – Totals a numeric property or column. Use this for value-based metrics like revenue or token consumption.

When you select **Sum**, specify which property (for events) or column (for Data Warehouse) to aggregate. For example, sum the `amount` column on a Stripe charges table to track total revenue.

### Display

Choose how the metric is visualized on customer profiles:

- **Number** – Shows a single numeric value with a percentage change indicator. This is the default.
- **Sparkline** – Shows a bar chart of daily values over the selected interval, along with the total value and percentage change. Useful for spotting trends at a glance.

## Manage usage metrics via MCP

The [PostHog MCP server](/docs/model-context-protocol) enables AI agents to programmatically manage usage metrics. You can create, update, list, and delete usage metrics directly from any MCP client like Cursor, Claude Code, or VS Code.

The following MCP tools are available for usage metrics:

| Tool                           | Description                           |
| ------------------------------ | ------------------------------------- |
| `usage-metrics-create`         | Create a new usage metric             |
| `usage-metrics-list`           | List all usage metrics in the project |
| `usage-metrics-retrieve`       | Get a single usage metric by ID       |
| `usage-metrics-partial-update` | Update an existing usage metric       |
| `usage-metrics-destroy`        | Delete a usage metric                 |

Try these example prompts with your MCP-enabled agent:

- `List all usage metrics in my project.`
- `Create a usage metric that counts api_request events over the last 30 days.`
- `Update my API calls metric to use a 90-day interval.`
- `Delete the usage metric with ID 123.`

See the [MCP server documentation](/docs/model-context-protocol) for setup instructions.
